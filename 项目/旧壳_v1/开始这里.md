# 开始这里

> 本项目使用“小陌 AI 影视工作流 v0.7”。新建项目由 `$start-ai-film-project` 从权威模板创建。
> 本文件是日常入口；项目根目录以本文件所在目录为准，不依赖旧聊天或旧电脑路径。

## 日常路线

```text
A 分配一个任务
→ B/C/D 完成该任务
→ 明确确认后写回
→ 更新最近交接
→ 返回 A 分配下一任务
```

完整生产链为：

```text
点子 → 剧本 → 资产 → 色卡 → 表演 → 镜头 → 提示词 → 生成反馈
→ 剪辑成片 → 发布包 → 数据与流程复盘
```

## 必须遵守的契约

1. 项目文件是长期事实源，聊天记录不是。
2. A 每次只分配一个任务；B/C/D 只执行 A 当前分配给本岗位的任务。
3. 每个岗位只写自己的主文件和专属目录，其他文件只能读取。
4. 草案阶段零写入。只有“明确采用”才写成采用；暂停、切换岗位或结束本轮只能写“待定摘要＋最近交接”。
5. 项目持久状态只使用 `待定`、`采用`、`停用`。“候选”“开放问题”“用户确认”“AI 推断”只可作为对话标签。
6. 写入前重新计算目标文件 SHA-256；若与本轮首次读取值不同，立即停止并报告并发修改，不覆盖。
7. 生成媒体、执行剪辑、上传或发布都需要单独的明确执行授权。授权采用方案不等于授权执行外部动作。
8. A/B/C/D 若观察到重复返工、遗漏、交接失败、职责冲突、重复手工步骤、工具失败、证据缺口或契约不清，使用 `$improve-ai-film-workflow` 静默写入 `流程改进日志/`。普通创作修改不记录；日志由该 Skill 独占写入，不改变岗位原有文件边界，也不自动修改总工作流。阻塞、覆盖、数据丢失、权限和安全风险仍须立即报告。
9. 没有可用工具时交付 `manual-copy` 人工执行包，不声称已生成、已剪辑、已上传或已发布。

“采用这个”“按这个定稿”可视为采用确认；“先看看”“大概这样”“以后再说”仍是待定。遇到含糊表达只问一个最关键的问题。

## 文件归属

| 岗位 | 独占写入 |
| --- | --- |
| A_总控流程 | `A_总控.md` |
| B_故事剧本 | `B_故事剧本.md` |
| C_视觉生成 | `C_视觉生成.md`、`资产设计/`、`色卡/`、`表演设计/`、`镜头规划/`、`提示词卡/`、`生成记录/`、生成素材 |
| D_后期发行复盘 | `D_后期发行复盘.md`、`后期方案/`、`发布包/`、剪辑成片、声音与封面资产 |

生成素材保存到 `assets/视频/生成素材/`；粗剪和成片保存到 `assets/视频/剪辑成片/`，双方不得覆盖对方文件。

## 问题路由

```text
故事、人物、情绪问题 → B
资产、表演、镜头、提示词、模型限制或生成问题 → C
剪辑、声音、字幕、成片、发行或数据复盘问题 → D
无法判断、跨岗位冲突或里程碑关闭 → A
```

一次生成失败不能直接触发全故事重写。先由 `$produce-and-review-ai-media` 分类，再只返修最小责任层。

## A_总控流程启动词

```text
A_总控流程｜旧壳_v1

请使用 $orchestrate-ai-film-project，并读取项目根目录中的“开始这里.md”和“A_总控.md”。
你只负责读取各岗位最近交接、判断当前状态、安排一个当前任务、处理岗位切换和关闭里程碑，并且只写 A_总控.md。
每个任务必须写清：执行岗位、输入、明确不做、完成标准、写回位置。不要代替 B/C/D 制作内容。
项目尚未开始时，把第一个最小任务交给 B；岗位返回时先核对其最近交接和证据，再决定下一步。
遵守草案零写入、明确确认门和写前哈希复核。若 A 当前任务尚未完成，不并行分配第二个任务。
若发现流程级问题，调用 $improve-ai-film-workflow 静默登记后继续调度；不要直接编辑流程改进日志，也不要因普通记录打断当前任务。
```
