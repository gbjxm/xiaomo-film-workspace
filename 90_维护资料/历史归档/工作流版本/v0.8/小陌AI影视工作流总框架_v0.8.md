# 小陌AI影视工作流总框架 v0.8

状态：正式活动版本。采用局部能力标识控制兼容补丁；`workflowPatch: single-foreground-micropatch-v1` 管理单一前台微补丁，`workflowResume: same-role-resume-v1` 管理 B/C/D 同岗续接，`workflowScript: b-word-stage-ready-v1` 管理 B 专业自检、A 完整性审查与 Word 协同。版本号仍为 v0.8；正式安装状态以根 `HANDOFF.md` 与正式验收报告为准。

## 1. 目标与本次边界

v0.8 把 C 的视觉生产与 D 的后期完成连接为一条可追溯状态脊柱，同时保留 v0.75 的 E_发行复盘安全链：

```text
点子 → 采用 Sxx → 项目视觉/制作基准＋条件性后期预设
→ Axx／色卡／表演／Vxx → Vxx Setup vNN → 提示词卡
→ Vxx-Bnn-Tnn 真实 take → C 交 D 素材清单 → D 接管快照
→ CUTxx vNN → Picture Lock → PIC/AUD/TEXT/GFX
→ 精确 Master＋自动检查＋人工完整观看/核听＋恢复验证
→ A 验收并派 E
→ 包装决定 → 最终封面 → 唯一最终发布包 → 独立发行就绪检查
→ manual-copy 人工发布 → 真实平台回执 → 单片发行复盘
```

首版只覆盖能运行的核心岗位，不建立自动上传、多账号矩阵、复杂增长系统、全自动数据抓取或长期账号战略。短视频平台是下游包装与发行变量，不反向吞并故事、视觉和成片判断。

## 2. 新项目启动

使用 `$start-ai-film-project` 从 v0.8 权威模板创建新项目。启动器负责版本化目录、模板复制、完整性校验、项目身份、日志目录和五岗位原始提示词，并交付一段轻量单提示词启动包；它不是第六岗位。

用户在新项目第一个任务中发送启动包。当前任务成为 A，再创建 B/C/D/E 四个独立本地待命任务。待命任务创建时不加载岗位 Skill、不读取项目文件，也不提前执行空派工；用户第一次进入该岗位后，任务才从项目 `开始这里.md` 读取共享契约与本岗位启动词。项目内 `开始这里.md` 是唯一日常入口。

## 3. 五岗位与写入权

| 岗位 | 负责 | 独占写入 |
| --- | --- | --- |
| A_总控流程 | 单一任务、输入与边界、完成标准、岗位切换和里程碑 | `A_总控.md` |
| B_故事剧本 | 点子、故事骨架、人物、主题、剧本和制作启动判断 | `B_故事剧本.md` |
| C_视觉生成 | 场景导演基准、生产设计、色彩意图、表演、摄影灯光、镜头、Setup、提示词、媒体生成、take 准入与精确素材交接 | `C_视觉生成.md`、`场景制作/`、C 专属目录与生成原始素材 |
| D_后期剪辑 | 素材接管、入片选择、剪辑与锁画、PIC/AUD/TEXT/GFX、Master、QC、恢复与权利证据 | `D_后期剪辑.md`、`后期方案/`、D 派生资产与母版 |
| E_发行复盘 | 平台包装、最终封面、发行就绪检查、人工发布交接、回执和真实数据复盘 | `E_发行复盘.md`、`发布包/`、`assets/封面/` 中的发行封面 |

其他岗位只能读取 A 指定的最小材料，不能代写。C 的生成视频位于 `assets/视频/生成素材/`，D 的剪辑成片位于 `assets/视频/剪辑成片/`，E 的发行封面位于 `assets/封面/`，不得覆盖彼此文件。

用户停留在哪个任务不改变文件所有权。当前岗位可以发起后台微补丁，但目标文件仍必须由表中所属岗位的 Skill 或受限执行者写入；当前岗位不得借“体验优化”直接代写其他岗位文件。

`流程改进日志/` 是岗位写入边界之外的固定例外，由 `$improve-ai-film-workflow` 独占写入。岗位只能调用该 Skill 登记流程问题。

## 4. 统一执行契约

每个项目模式 Skill 必须明确：

```text
读取范围
写入范围
确认门
负责的 ID
停止条件
交接目标
```

执行规则：

1. 首次进入普通任务只读项目入口的共享契约与本岗位启动词、A 当前任务、本岗位主文件和 A 指定的最小材料；跳过其他岗位启动词。同一任务未变化的公共上下文直接复用。受限后台所有者模式只读微补丁请求、目标对象/索引、A 指纹、预期 hash 和不变量，默认跳过常规专业 references；差量本身需要新专业判断时才按需加载。
2. A 给 B/C/D 分配完整阶段目标，不按故事骨架、初稿、单项资产、单次生成、粗剪或单个后期组件等微步骤拆成多个 A 任务。
3. 当前岗位是本阶段中控。只要目标岗位、采用的上游稳定 ID/核心事实、阶段目标、写回范围和外部动作授权边界都未改变，岗位内追问、版本迭代、局部返修和同岗位 Skill 切换都留在本岗位。
4. 跨岗位不自动等于重大变化。若用户已经明确采用一个具体差量并授权把该差量写入项目记录，且只涉及当前岗位与一名上游文件所有者，稳定 ID、制作功能、事件顺序与结果、阶段目标、任务包络、Profile/平台/主要传播承诺及授权类别均不变，不触及已冻结/锁定下游，影响能在当前阶段精确判定并一轮恢复，则使用“单一前台＋后台所有权微补丁”。纯“采用/定稿”不等于记录写入授权；同一条消息只有明确要求“修改、更新或写入”精确对象时才可同时作为两项证据。
5. 微补丁由当前岗位只读预检并发送最小差量包：项目根、来源任务 ID、交互前台、A 权威执行目标及当前任务版本/hash、可定位的用户采用证据与记录写入授权证据、目标所有者、对象旧版/hash、采用差量、不变量、受影响执行坐标、失效范围、现有外部动作授权、恢复条件。所有者写前复核 hash，只改自己的文件、保持稳定 ID 并按契约升版；只有既有 A 指针失效时，A 后台同步精确版本/hash，不复审创作内容、不展开暂离/恢复、不增加往返次数。当前岗位重读新版本和指针后继续，用户不切任务、不复制内部交接，只看到一次必要决定与一次结果。
6. 默认在同一前台回复内顺序激活受限文件所有者适配器、A 指针适配器和前台重绑，不新建完整代理任务。只有差量需要新的专业判断、当前运行时无法保证写入白名单或独立上下文能显著降低错误风险时，才降级到既有所有者任务/受限子任务；用户仍不承担切换与复制。适配器细则由 A 的轻量适配器契约统一维护。
7. 目标 hash 变化、所有者或项目不唯一、影响扩到第二个上游岗位、已传播到无法在当前阶段安全失效的锁定下游，或一轮不能完成时，微补丁零覆盖停止并升级 A。所有者已写而 A 同步失败时保留真实新版本并凭回执恢复指针；同步完成而当前岗位重绑定失败时停止执行外部动作，不回滚历史采用事实。
8. “交互前台”是用户停留的任务，“权威执行目标”是 A 当前允许写入的岗位；平时二者相同。微补丁不改变权威目标，所有者只作为受限子操作执行。重大串行路由由 A 改变权威目标并填写正式暂离/恢复字段，原交互前台进入暂停，恢复前不得继续使用旧输入或写入依赖产物。
9. 用户明确称为重大修改，或新增/删除场景、稳定对象，改变核心事件、人物动机、关系结果、结局、稳定对象制作功能、剪辑结构目标、Output Profile、平台/主要传播承诺、项目目标/里程碑/任务边界、权利/安全状态或外部动作类别时，必须交 A 决策。当前任务已预列的生成或剪辑授权可在本岗位等待用户决定；阶段内预期创建首个稳定 ID 也是正常进展。完成整个阶段只回 A 一次。
10. 草案、咨询、诊断和只读检查零写入，不计算 SHA-256。
11. 获得记录写入授权并即将写入时，重读目标、记录 SHA-256，紧邻写入前再次核对；发生变化时停止。
12. 候选、方向、提示词、计划和未执行动作不能写成采用或完成。
13. 用户暂停、切换岗位或结束本轮但没有采用时，只有明确要求记录才写待定摘要和最近交接。
14. 采用、记录写入、生成媒体、剪辑执行、封面媒体制作或改写、安装、晋升、项目迁移、上传和公开发布分别需要明确授权。微补丁的一次记录写入授权只原子覆盖：所有者精确对象、必要 A 指针同步和前台引用/失效登记；不扩张任何外部动作授权。
15. 工具不可用、输入缺失或执行失败时返回真实状态和最小恢复条件，不声称完成，也不得把内部路由转嫁为用户手工复制。

“采用”“就这样”“按这个定稿”只证明采用；“按这版写入”“就按这个改”“更新这个文件”在对象与差量明确时可同时证明采用和该原子记录写入授权；“先看看”“可能”“不一定”仍是待定。“请生成”“请剪出文件”“请制作封面文件”“请上传或公开”只授权所点名外部动作。

### B 专业自检、A 完整性审查与 Word 精修

本节只在项目入口声明 `workflowScript: b-word-stage-ready-v1` 时启用；未声明的既有 v0.8 项目继续按原入口，不自动迁移 A/B、Word 或历史正文。

既有项目若已经完成 B 且 A 正在 C/D/E，可只同步入口和空 `剧本/` 目录并前瞻启用：不追溯要求旧 B 重做完成包，不使已有锁定 Word、Sxx 或当前下游任务失效；下一次完整 B 阶段正常完成时才首次强制本契约。C 中的一处 B 微补丁仍按原微补丁门执行，不等于重开完整 B 阶段。

B 与 A 共同引用唯一 `B_STAGE_READY v1`，不得各自维护第二套故事完成标准。B 是专业审查者：在本岗完成创作、正文、AI 可制作性、精确剧本工件、Sxx、阻塞项和证据的详细检查；任一必需项未通过时继续留 B，不把半成品交 A。用户的创作采用仍是必需事实，B 的 PASS 只表示在已约定标准下没有已知制作阻塞，不冒充作品客观完美。

B 只在 PASS 后提交一次阶段完成包。A 仍执行验收，但只核对完成包是否缺项、路径/版本/hash 是否当前、用户采用与记录/制作释放证据是否存在、阻塞项是否为零、Sxx 范围与任务包络是否一致；A 不重新运行五书会诊，不逐场复审对白、人物、因果或风格，也不得临时增加共享契约之外的创作标准。机械缺项由原 B 在后台刷新，不要求用户往返切换；完整性通过后 A 直接派 C，媒体生成授权仍独立。

故事骨架与结构探索默认留在对话和 B 记录中。进入正式对白、场景动作、故事层场记/连续性、计时或最终文字精修时，可启用 `剧本/` 下的 Word 协同：用户平时只面对活动 Word；Codex 以最近保存点为基线生成修订、批注或副本。用户继续编辑时允许后台并行差量，非重叠修改可汇合为新候选，重叠段落必须显式交用户选择。当前能力不假设能读取 Microsoft Word 中未保存的文字，任何 Codex 写入都不得覆盖用户未同步内容。

剧本工件身份以 B 登记的路径、版本、SHA-256 和用户决定为准，不能只凭文件名、Word 内部标题或修改时间猜测。采用源稿保持不可变；生产稿是可选派生物，用户指定原文件为最终版时必须写 `不适用＋原因` 并原样保留。B 主文件不堆积多版历史全文，旧工作稿/候选移入 `剧本/历史/` 且默认不进入启动读集；历史保留深度由项目决定，不自动删除。

Word 场次使用稳定锚点映射 Sxx。C 启动后若只修改同一场次且制作功能不变，保留 Sxx 并升版，只使受影响的 C 依赖待复核；改变事件结果或制作功能才新建/停用 Sxx，不能因整份 Word hash 改变而机械让全剧下游失效。

### 同岗新任务续接

启用 `same-role-resume-v1` 的项目用项目内非权威续接缓存连接 B/C/D 的多个本地任务。A 的完整阶段包络继续保持，例如 C 可覆盖 `S01—S21`；阶段包络不是启动读取列表，岗位缓存中的当前执行游标和精确读集才是新聊天的启动输入，不能把阶段包络展开成全量读取。

```text
旧岗位任务或用户手动新建
→ 读取入口岗位段＋A 当前任务区段＋岗位缓存
→ 校验 revision / lease / A门禁 / 局部依赖hash
→ 有效：只读当前对象 requiredReadSet
→ 局部漂移：只重读变化对象及显式依赖
→ 缓存损坏：区段级恢复；无法唯一定位时问一个问题
```

续接缓存同时保存正式事实指针和待定工作游标，二者必须分层：正式事实仍由岗位权威文件拥有；待定草稿、上一版完整提示词或未回答问题可以被缓存以避免用户复制，但永远保持待定。新任务、缓存校验或历史摘要都不能把它们升级为采用。

自动入口只在用户明确要求创建新同岗任务时触发；旧任务先写 `handoff_pending`，新任务成功创建并激活租约后旧任务停止写入。手动入口由新任务 Claim 最新缓存；若已有其他任务的未过期 lease，必须同时具有用户明确切换证据和旧任务已停止/空闲证据，否则停止并改走自动 handoff。所有缓存更新使用 revision＋lease 乐观并发门；新聊天本身不改变 A 权威目标、岗位文件所有权、稳定 ID、里程碑或任何外部动作授权。

B 按当前场次/Sxx 恢复，只有全剧会诊、整体重写、Word 无差量漂移、全片计时或版式 QA 才扩大读取；C 分开阶段包络与活动 S/A/V/功能站，候选素材树默认排除；D 状态查询不重开工程或媒体，只有入片/声画判断、实际续剪、QC 或恢复证据所需时才打开精确对象。

## 5. 状态、版本与 ID

项目持久采用状态只使用：

```text
待定
采用
停用
```

执行有效性另用 `未触发 / 进行中 / 已冻结 / 已失效 / 不适用＋原因`。历史采用事实不得因上游变化被抹除；当前执行版本可以失效。发行阶段如“封面已采用、已就绪待人工发布、已发布”也是执行阶段，不替代采用状态。

| ID | 对象 | 唯一分配者 |
| --- | --- | --- |
| `Sxx` | 可进入制作的剧本段落 | B 的剧本开发 Skill |
| `Axx` | 角色、场景、道具等视觉资产 | `$design-ai-film-assets` |
| `Vxx` | 镜头计划到生成和剪辑的稳定镜头 | `$plan-ai-shots-and-previs` |
| `CUTxx` | 首个真实可比较粗剪或成片 | `$edit-and-finish-ai-film` |
| `PUBxx` | 单一 CUT、平台与传播承诺的发行对象 | `$package-video-release` |

纯方向候选不分配稳定 ID。真实、可播放且可比较的首个粗剪由 D 分配待定 `CUTxx`；采用另行确认。功能不变的小修订保留稳定 ID 并递增版本；功能根本改变时停用旧 ID、新建 ID，编号永不回收。`Setup`、批次、take、PIC/AUD/TEXT/GFX 与 Master 都是执行坐标、组件或版本，不新增稳定影视对象 ID。一个 PUB 只对应一个平台，抖音和 B站分别记录。

## 6. C+D 联合生产路线

### 6.1 条件性后期预设

普通短片引用默认后期 Profile。规格不明、对白或音乐先行、口型同步、VFX、多版本输出、非默认时基/画幅或特殊字幕等风险出现时，A 暂派 D 建立一页后期预设；它必须在首个受影响 Setup 锁定和生成前完成。A 始终只派一个当前岗位，并记录来源任务、返回岗位、恢复对象与精确版本、恢复条件和往返次数。

### 6.2 C 六个功能站

每个采用 Sxx 从六种功能视角检查：场景导演、生产设计与资产、表演与调度、摄影灯光与镜头、数字拍摄与生成、场记审查与交接。六站不是六个人、六个聊天框、六个 Skill 或六份强制文档。每个 Sxx 最多一张场景制作卡；简单空镜或插入镜头可记录理由后跳过不适用站，无人物表演可跳站 3。C 的静态/动态预演和滚动组接不占 CUT，只作生成/衔接参考，也不代表真实剪辑授权。

`Vxx Setup vNN` 原子绑定：Sxx 与导演基准、Axx 与必要资产文件、采用色卡/视觉弧线、表演与调度、Vxx 镜头方案、真实输入路径和 SHA-256、默认 Profile 或条件性后期预设、工具限制、输出规格、声音/口型/剪辑接口，以及未解决项和责任人。任一必需采用版本缺失、冲突或变化时，Setup 不就绪或旧版失效；相关提示词适用性和 take 准入同步待复核，真实旧 take 只保留为历史。

每个真实 take 使用 `Vxx-Bnn-Tnn`，记录路径、SHA-256、时长、帧率、音轨、输入、参数、实际差异与 C 准入结论。C 只能结论“当前 C 准入自检通过，可交 D 组接候选”，不能宣称真实可剪已证明。

### 6.3 C 交接与 D 接管

C 独占的交 D 素材清单绑定精确 S/A/V、场景卡、Setup、提示词卡、生成记录、推荐/备选/停用 take、路径/hash/媒体属性、把手、动作/反应/空间/声音接口、实际差异、限制和功能化 coverage owed。A 只保存该清单当前路径与版本指针，不复制正文。

D 建立自己独占的接管快照，重新核验路径、SHA-256、可打开性、代理/派生关系、工程版本和参考导出。D 不重命名、覆盖或修改 C 原始媒体；代理、转码、稳定化或修复件必须记录“源 take 路径/hash → D 派生路径/hash → 参数 → 用途”。C 的 take 准入不替代 D 的精确入片选择；D 不得静默使用 C 已停用 take。

### 6.4 CUT、锁画、组件与 Master

```text
C 可交 D 组接候选
→ A 派 D 并单独确认真实剪辑授权
→ D 建立接管快照和首个真实可比较粗剪，分配待定 CUT
→ 用户采用 CUT
→ 对精确 CUT 版本确认 Picture Lock
→ PIC/AUD/TEXT/GFX 按风险完成并冻结
→ Master 精确绑定 CUT、组件、路径/hash 与 Output Profile
→ 自动检查＋人工完整观看/核听
→ 重开工程、重连采用媒体并再次输出的恢复验证
→ D 将完成证据交回 A
```

```text
CUT 创建 ≠ CUT 采用 ≠ Picture Lock ≠ 组件冻结 ≠ Master 绑定 ≠ Master QC 通过
```

只有顺序、切点、时长或采用媒体变化才令同一剪辑功能的 `CUTxx` 递增版本；剪辑方向根本改变才新建 CUT。新 CUT 版本不继承旧 Picture Lock。单独修改 AUD/TEXT/GFX 等组件只使依赖它们的组件、Master 和该版 QC 失效，不无差别使 PIC 或 CUT 失效。旧组件不得静默混入新 Master。

### 6.5 最小返修与失效传播

D 返回 C 必须记录 CUT 时间点、S/V、缺少的叙事功能/反应/动作阶段/空间基准/插入/声音接口、现有素材为何不可替代，以及最接近证据的责任站。可由 D 通过入出点、匹配、声音或后期修复解决的问题不退 C。同一镜头功能保留 V 并提升 Setup/take；功能改变才停用旧 V、新建 V。逻辑路由仍最多一轮 `D→A→C→A→D`，但用户可始终留在 D 前台，由后台所属岗位完成并自动恢复；每次真实生成与剪辑仍分别授权，第二轮仍不成立时停止给用户/A。

上游规格变化只使受影响 Setup、提示词适用性、take 准入和 C 清单失效。take 路径/hash 变化先由 D 的精确素材使用表判断：未被当前 CUT 使用则不污染 CUT；已使用才触发 CUT 升版与 Reconform。任一 Master 绑定输入变化都使该 Master 与 QC 结论失效。

D 的质检只判断影片本身；不判断平台标题、封面、平台字段或发布授权。D 不生成替代素材，不建立 PUB、不写 E，也不直接启动 E。

## 7. A 到 E 的发行路线

只有以下证据齐全，A 才能派 E：

- 采用的 `CUTxx vNN` 及其 Picture Lock 状态明确。
- 精确 Master 路径、版本、SHA-256 和 Output Profile 齐全。
- PIC/AUD/TEXT/GFX 精确版本和状态齐全。
- 自动检查与人工完整观看/核听均有真实证据，剩余风险已决定。
- 工程/采用媒体恢复位置与验证结果、来源/权利/真人声音同意/AI 状态证据齐全。
- 当前项目真实存在 E 契约；旧项目无 E 时不得补建。

E 的四项单职责能力按依赖运行：

| Skill | 唯一职责 | 不负责 |
| --- | --- | --- |
| `$package-video-release` | 实际审看精确 Master，采用包装决定后独占分配 PUB；封面完成后组装唯一最终发布包；登记真实回执与实际字段 | 不制作最终封面，不给就绪结论，不改母版，不自动发布 |
| `$design-video-release-cover` | 从精确 Master 或合法采用资产制作并验收真实最终封面文件 | 不另写标题，不分配 PUB，不重做影片核心视觉，不改母版 |
| `$check-video-release-readiness` | 对精确最终发布包、Master 和封面哈希独立检查事实、当前规则、权利隐私、首映/投稿资格和动作字段 | 不修稿改图，不另写 manual-copy，不重复 D 质检，不上传发布 |
| `$review-ai-film-results` | 用真实数据区分事实、反馈、假设，并提出下一次一组调整 | 不制定长期账号战略，不审计全制作链，不改 PUB |

推荐任务分段：

1. **发行准备**：采用包装决定并分配 PUB，完成封面，再组装唯一最终发布包并通过精确版本检查。
2. **发布登记**：用户人工发布并带回真实回执后，记录实际标题、正文、封面、账号、可见性、链接、时间及与计划差异。
3. **发行复盘**：达到观察窗口且有真实数据后，形成单片复盘。

这样不让一个 A 任务因等待发布日期或数据长期悬空。

## 8. 发行安全门

### 精确 Master 门

包装必须实际查看 A 指定且通过 D 完成门的精确 Master，并绑定 CUT vNN、Master 路径/版本/hash、Output Profile、PIC/AUD/TEXT/GFX 状态、QC 与恢复证据。只有 CUT 编号、剧本、摘要、旧导出、缺 hash/Profile/组件状态或失效路径时停止。E 需要新画幅、重编码、烧录字幕/字幕版、音轨版或成片修复时，逻辑上执行 `E→A→D→A→E`，用户可留在 E 前台；A 后台冻结恢复对象，D 独占制作新 Master 并完成 QC，A 重验完成门后自动恢复 E。E 不自行修改母版，转码或剪辑执行仍需独立授权。

### 最终封面门

封面方向、提示词或 mockup 不等于最终封面。必须存在真实可打开的文件，记录来源帧时间点或资产、授权、版本、SHA-256、规格和缩略图验收。需要重做影片核心视觉时交 A 路由 C 或 D。

### 唯一最终发布包门

包装决定和最终封面齐全后，由 `$package-video-release` 组装唯一最终发布包。该包锁定包装决定、精确 Master、封面记录和封面文件的路径、版本与 SHA-256，并独占保存 manual-copy。采用后不原地改写；Master、其绑定组件、其他输入、文字或平台字段变化都新建版本并使旧发布包与旧检查结论失效。

### 当前规则与权利门

平台规格与政策容易变化。发行就绪检查必须查询当次官方来源并记录链接和日期；无法核验时保持待确认。第三方词库只能发现线索，不能代替官方规则与人工语境判断。权利、隐私和敏感风险缺证据时不得判通过。

公开发布还必须明确“保留首映或投稿资格：需要 / 不需要”。未确认不能通过；需要时由 A 调用 `$manage-film-competition-submissions` 核实本届规则与公开条件，避免不可逆地损失投稿资格。

### 发布授权门

v0.8 首版只输出 `manual-copy`，不控制浏览器、不登录账号、不上传、不定时、不公开、不修改或下架内容。

```text
包装决定采用 ≠ 封面完成
封面完成 ≠ 最终发布包采用
最终发布包采用 ≠ 精确版本检查通过
检查通过 ≠ 上传授权
上传或草稿 ≠ 公开发布
没有真实回执 ≠ 已发布
```

## 9. 结果复盘

只有真实 PUB 回执和平台数据存在时复盘。若实际发布字段与最终发布包不同，以回执中的实际版本为分析对象并保留差异。每条结论分四层：

1. 数据事实。
2. 有样本边界的反馈。
3. 一个主要解释与至少一个替代解释。
4. 下一次只调整的一组变量。

没有真实数据只记录“等待观察”。单条作品不能确立或推翻长期账号方向，不把平台波动自动归因于作品质量。

## 10. 里程碑

| 里程碑 | 最小证据 |
| --- | --- |
| 后期成片完成 | 采用 CUT vNN、Picture Lock、精确 Master 路径/版本/hash/Profile、组件状态、自动＋人工 QC、限制、恢复与权利证据 |
| 发行已就绪 | 采用 PUB、真实最终封面、唯一最终发布包及其输入哈希、明确首映/投稿决定和绑定精确版本的独立检查通过 |
| 公开发布已登记 | 真实平台、账号、实际发布字段、链接或明确回执、发布时间及与计划差异 |
| 单片发行复盘完成 | 真实数据窗口、事实、样本限制、主要与替代假设、下一次单一调整 |

发布是用户可选择的外部动作。未发布或尚未到观察窗口不等于制作失败，只保持相应里程碑待定。

## 11. 返修路由

先判断是否仍在同一阶段边界内：B 中不改变已采用故事功能的措辞、动作、节奏和版本调整留在 B；C 中不改变 Sxx 核心事实与镜头叙事功能的资产、色卡、表演、镜头、Setup、提示词和 take 调整留在 C；D 中不要求新源画面、不改变故事事实且仍在既有剪辑授权与 Output Profile 内的入出点、节奏、声音、字幕/GFX、Online、调色和组件版本调整留在 D；E 中同一 CUT/Master/平台/主要传播承诺下的标题、正文、标签、封面和包版本调整留在 E。证据指向一名其他文件所有者但满足第 4 节微补丁条件时，由当前岗位后台直达该所有者并自动续办；不满足时才交 A 决策。

| 证据指向 | 返回 |
| --- | --- |
| 故事、人物、主题、情绪或可见行动 | B |
| 场景导演、生产设计、表演、摄影灯光意图、镜头、提示词、源画面或生成一致性 | C |
| 接管、入片选择、节奏、声音、画外字幕/GFX、Online、最终调色、Master 或恢复 | D |
| 标题、正文、发行封面、平台字段或包装反馈 | E |
| 权利风险、无法判断、跨岗位或里程碑 | A |

E 不能直接修改 B/C/D。合格的单跳微补丁可由 E 在当前任务后台请求所属岗位；成片派生仍走后台 `E→A→D→A→E`，重大变化交 A。单条数据不触发全流程重做。

## 12. 写回与交接

B/C/D/E 在任务完成、暂停、切换岗位或结束本轮时按本岗位契约更新最近交接：

```text
本次完成：
已经写入：
仍然待定：
发现的问题：
建议下一步：
需要 A 判断：
```

A 验收真实证据后更新自己的当前任务和里程碑。岗位不直接修改 A。

后台微补丁回执固定只含：来源任务 ID、A 当前任务指纹、采用/记录写入授权定位、对象 ID 与旧版→新版、所属岗位写入路径与新 SHA-256、实际差量、不变量回归、受影响执行坐标、失效/待复核清单、A 指针同步结果和前台恢复状态。内部任务包不复制到用户回复；用户只收到创作结果、必要风险和唯一下一步。

## 13. 流程改进与旧项目兼容

A/B/C/D/E 在真实任务中观察到重复返工、遗漏、交接失败、职责冲突、重复手工、工具失败、证据缺口或契约不清时，调用 `$improve-ai-film-workflow` 登记 WFI。普通创作修改不记录，日志不自动改总工作流。

机器安装 v0.8 不代表当前项目已迁移：

- 新建 v0.8 项目只有入口声明 `workflowPatch: single-foreground-micropatch-v1` 时启用本补丁；无标识的既有 v0.8 项目继续按原跨岗位规则运行，不能因机器安装自动启用。
- v0.75 且真实存在 E 时继续按其原契约运行。
- v0.7 或更早且无 E：继续按原项目契约运行，不补建 E。
- 共用 Skill 必须从当前项目入口和文件结构判断，不能只看机器配置版本。
- 迁移旧项目需要单独明确授权。

比赛投稿管理仍是五岗位之外的根级能力，不新增第六聊天框。项目有 E 时可读取真实公开链接与发行状态；旧项目无 E 时保持兼容。

## 14. 工具中立

核心文件只保存平台无关的事实、稳定 ID、约束、输入输出和证据。具体生成、剪辑、封面或发布工具通过可替换适配器执行。首版默认 `manual-copy`：

```text
AI 输出可复制任务包
→ 用户在外部工具执行
→ 用户带回文件、链接、回执或数据
→ 所属岗位核验并登记
```

没有适配器时不猜参数、不虚构执行。
