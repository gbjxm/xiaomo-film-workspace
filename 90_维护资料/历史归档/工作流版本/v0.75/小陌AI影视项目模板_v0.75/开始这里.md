# 开始这里

> 本项目使用“小陌 AI 影视工作流 v0.75”。新建项目由 `$start-ai-film-project` 从权威模板创建。
> 本文件是日常入口；项目根目录以本文件所在目录为准，不依赖旧聊天或旧电脑路径。

## 日常路线

```text
A 分配一个任务
→ B/C/D/E 中唯一目标岗位完成该任务
→ 明确确认后写回
→ 更新最近交接
→ 返回 A 分配下一任务
```

同一 A 当前任务内的追问、局部返修和同岗位续办不必返回 A；只有任务完成、跨岗位、影响里程碑或出现阻塞时才回 A。

完整生产链为：

```text
点子 → 剧本 → 资产 → 色卡 → 表演 → 镜头 → 提示词 → 生成反馈
→ 后期剪辑 → CUT 成片与质检 → 包装决定 → 最终封面 → 唯一最终发布包 → 发行就绪检查
→ manual-copy 人工发布 → 真实回执 → 发行结果复盘
```

## 必须遵守的契约

1. 项目文件是长期事实源，聊天记录不是。首次进入任务只读取本文件的共享契约与本岗位启动词，跳过其他岗位启动词；同一任务内未变化的已读内容直接复用。
2. A 每次只分配一个任务；B/C/D/E 只执行 A 当前分配给本岗位的任务。
3. 每个岗位只写自己的主文件和专属目录，其他文件只能读取。
4. 草案阶段零写入。只有“明确采用”才写成采用；暂停、切换岗位或结束本轮只能在明确要求记录时写“待定摘要＋最近交接”。
5. 项目持久状态只使用 `待定`、`采用`、`停用`。“候选”“开放问题”“用户确认”“AI 推断”只可作为对话标签。
6. 草案、咨询、诊断和只读检查不计算 SHA-256。明确采用并即将写入时，先重读目标并记录 SHA-256，紧邻写入前再次核对；值变化时停止，不覆盖。
7. 生成媒体、执行剪辑、制作或改写封面媒体、上传和公开发布是彼此独立的外部动作，分别需要明确授权。采用方案不等于授权执行。
8. v0.75 首版不自动登录、上传或公开发布；E 只交付经过检查的 `manual-copy` 包。没有真实链接或平台回执时不得登记已发布。
9. 公开发布前必须明确“保留首映或投稿资格：需要 / 不需要”。未确认时不能判就绪；需要时交 A 调用 `$manage-film-competition-submissions` 核实公开条件。
10. A/B/C/D/E 若观察到重复返工、遗漏、交接失败、职责冲突、重复手工步骤、工具失败、证据缺口或契约不清，使用 `$improve-ai-film-workflow` 静默写入 `流程改进日志/`。普通创作修改不记录；日志由该 Skill 独占写入，不自动修改总工作流。
11. 没有可用工具时交付真实的人工执行包，不声称已生成、已剪辑、已制作封面或已发布。

“采用这个”“按这个定稿”可视为采用确认；“先看看”“大概这样”“以后再说”仍是待定。遇到含糊表达只问一个最关键的问题。

## 编号与版本

| 编号 | 唯一分配者 |
| --- | --- |
| `Sxx` | B 的剧本开发 Skill |
| `Axx` | `$design-ai-film-assets` |
| `Vxx` | `$plan-ai-shots-and-previs` |
| `CUTxx` | `$edit-and-finish-ai-film` |
| `PUBxx` | `$package-video-release`，E 岗位 |

一个 PUB 只对应一个 CUT、一个平台和一个主要传播承诺。编号与版本分离；功能改变新建编号，旧编号标记停用且永不回收。

## 问题路由

```text
故事、人物、情绪问题 → B
资产、表演、镜头、提示词、模型限制或生成问题 → C
剪辑、声音、字幕、调色、视效修整、成片与母版问题 → D
标题、发布文案、发行封面、发布包、平台字段或发行数据 → E
无法判断、权利风险、跨岗位冲突或里程碑关闭 → A
```

一次生成失败或单条发布数据不能直接触发全故事重写。先按真实证据路由到最小责任层。
