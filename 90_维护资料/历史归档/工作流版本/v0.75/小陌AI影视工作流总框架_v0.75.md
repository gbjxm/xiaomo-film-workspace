# 小陌AI影视工作流总框架 v0.75

状态：活动版本。已完成隔离评测、用户确认、正式晋升与 18-Skill 安装；新项目默认使用本版，既有项目未自动迁移。

## 1. 目标与本次边界

v0.75 在 v0.7 的 A/B/C/D 生产链后增加 E_发行复盘，使工作流从“完成成片”延伸到“安全发行并从真实结果学习”：

```text
点子 → 剧本 → 资产 → 色卡 → 表演 → 镜头 → 提示词
→ 生成与结果诊断 → 后期剪辑 → CUT 成片与 D 质检
→ A 验收并派 E
→ 包装决定 → 最终封面 → 唯一最终发布包 → 独立发行就绪检查
→ manual-copy 人工发布 → 真实平台回执 → 单片发行复盘
```

首版只覆盖能运行的核心岗位，不建立自动上传、多账号矩阵、复杂增长系统、全自动数据抓取或长期账号战略。短视频平台是下游包装与发行变量，不反向吞并故事、视觉和成片判断。

## 2. 新项目启动

使用 `$start-ai-film-project` 从 v0.75 权威模板创建新项目。启动器负责版本化目录、模板复制、完整性校验、项目身份、日志目录和五岗位原始提示词，并交付一段单提示词启动包；它不是第六岗位。

用户在新项目第一个任务中发送启动包。当前任务成为 A，再创建 B/C/D/E 四个独立本地任务。项目内 `开始这里.md` 是唯一日常入口。

## 3. 五岗位与写入权

| 岗位 | 负责 | 独占写入 |
| --- | --- | --- |
| A_总控流程 | 单一任务、输入与边界、完成标准、岗位切换和里程碑 | `A_总控.md` |
| B_故事剧本 | 点子、故事骨架、人物、主题、剧本和制作启动判断 | `B_故事剧本.md` |
| C_视觉生成 | 资产、色卡、表演、镜头、提示词、媒体生成与结果诊断 | `C_视觉生成.md`、C 专属目录与生成素材 |
| D_后期剪辑 | 素材选择、剪辑、视效修整、声音、字幕、调色、成片质检和母版 | `D_后期剪辑.md`、`后期方案/`、D 资产 |
| E_发行复盘 | 平台包装、最终封面、发行就绪检查、人工发布交接、回执和真实数据复盘 | `E_发行复盘.md`、`发布包/`、`assets/封面/` 中的发行封面 |

其他岗位只能读取 A 指定的最小材料，不能代写。C 的生成视频位于 `assets/视频/生成素材/`，D 的剪辑成片位于 `assets/视频/剪辑成片/`，E 的发行封面位于 `assets/封面/`，不得覆盖彼此文件。

`流程改进日志/` 是岗位写入边界之外的固定例外，由 `$improve-ai-film-workflow` 独占写入。岗位只能调用该 Skill 登记流程问题。

## 4. 统一执行契约

每个项目模式 Skill 必须明确：

```text
读取范围
写入范围
确认门
负责的 ID
停止条件
交接目标
```

执行规则：

1. 首次进入任务只读项目入口的共享契约与本岗位启动词、A 当前任务、本岗位主文件和 A 指定的最小材料；跳过其他岗位启动词。同一任务未变化的公共上下文直接复用。
2. 草案、咨询、诊断和只读检查零写入，不计算 SHA-256。
3. 用户明确采用并即将写入时，重读目标、记录 SHA-256，紧邻写入前再次核对；发生变化时停止。
4. 候选、方向、提示词、计划和未执行动作不能写成采用或完成。
5. 用户暂停、切换岗位或结束本轮但没有采用时，只有明确要求记录才写待定摘要和最近交接。
6. 生成媒体、剪辑执行、封面媒体制作或改写、上传和公开发布分别需要明确执行授权。上一门确认不自动授权下一门。
7. 工具不可用、输入缺失或执行失败时返回真实状态和人工交接，不声称完成。

“采用”“按这版写入”“就这样”属于采用确认；“先看看”“可能”“不一定”仍是待定。“请生成”“请剪出文件”“请制作封面文件”“请上传或公开”只授权所点名动作。

## 5. 状态、版本与 ID

项目持久采用状态只使用：

```text
待定
采用
停用
```

发行阶段如“封面已采用、已就绪待人工发布、已发布”是对象的执行阶段，不替代采用状态。

| ID | 对象 | 唯一分配者 |
| --- | --- | --- |
| `Sxx` | 可进入制作的剧本段落 | B 的剧本开发 Skill |
| `Axx` | 角色、场景、道具等视觉资产 | `$design-ai-film-assets` |
| `Vxx` | 镜头计划到生成和剪辑的稳定镜头 | `$plan-ai-shots-and-previs` |
| `CUTxx` | 首个真实可比较粗剪或成片 | `$edit-and-finish-ai-film` |
| `PUBxx` | 单一 CUT、平台与传播承诺的发行对象 | `$package-video-release` |

候选不分配 ID。功能不变的小修订保留 ID 并递增版本；功能根本改变时停用旧 ID、新建 ID，编号永不回收。一个 PUB 只对应一个平台，抖音和 B站分别记录，避免文案、回执和指标定义混在一起。

## 6. A 到 D 的生产路线

v0.75 保留 v0.7 的制作契约：

```text
A 分配一个任务
→ B 建立并采用可制作 S
→ A 转交 C
→ C 建立 A 资产、色卡、表演、V 镜头、忠实提示词卡和真实生成记录
→ A 转交 D
→ D 建立并采用 CUT，完成影片本身的后期与成片质检
→ D 把 CUT、真实路径和质检证据交回 A
```

D 的质检只判断影片本身是否完成、可播放和符合成片要求；不判断平台标题、封面、版权声明、发布字段或授权。D 不建立 PUB、不写 E，也不直接启动 E。

## 7. A 到 E 的发行路线

只有以下证据齐全，A 才能派 E：

- `CUTxx` 状态为采用。
- 最终成片文件真实存在。
- D 成片质检结论通过或剩余风险已被用户明确接受。
- 当前项目真实存在 E 契约；旧项目无 E 时不得补建。

E 的四项单职责能力按依赖运行：

| Skill | 唯一职责 | 不负责 |
| --- | --- | --- |
| `$package-video-release` | 实际审看最终 CUT，采用包装决定后独占分配 PUB；封面完成后组装唯一最终发布包；登记真实回执与实际字段 | 不制作最终封面，不给就绪结论，不自动发布 |
| `$design-video-release-cover` | 从最终成片或合法采用资产制作并验收真实最终封面文件 | 不另写标题，不分配 PUB，不重做影片核心视觉 |
| `$check-video-release-readiness` | 对精确最终发布包、视频和封面哈希独立检查事实、当前规则、权利隐私、首映/投稿资格和动作字段 | 不修稿改图，不另写 manual-copy，不重复 D 质检，不上传发布 |
| `$review-ai-film-results` | 用真实数据区分事实、反馈、假设，并提出下一次一组调整 | 不制定长期账号战略，不审计全制作链，不改 PUB |

推荐任务分段：

1. **发行准备**：采用包装决定并分配 PUB，完成封面，再组装唯一最终发布包并通过精确版本检查。
2. **发布登记**：用户人工发布并带回真实回执后，记录实际标题、正文、封面、账号、可见性、链接、时间及与计划差异。
3. **发行复盘**：达到观察窗口且有真实数据后，形成单片复盘。

这样不让一个 A 任务因等待发布日期或数据长期悬空。

## 8. 发行安全门

### 最终 CUT 门

包装必须实际查看 A 指定的最终成片，记录真实时长和至少一个支撑传播承诺的时间点。只有剧本、摘要、旧剪辑或失效路径时停止。

### 最终封面门

封面方向、提示词或 mockup 不等于最终封面。必须存在真实可打开的文件，记录来源帧时间点或资产、授权、版本、SHA-256、规格和缩略图验收。需要重做影片核心视觉时交 A 路由 C 或 D。

### 唯一最终发布包门

包装决定和最终封面齐全后，由 `$package-video-release` 组装唯一最终发布包。该包锁定包装决定、视频、封面记录和封面文件的路径、版本与 SHA-256，并独占保存 manual-copy。采用后不原地改写；任何输入、文字或平台字段变化都新建版本并使旧检查结论失效。

### 当前规则与权利门

平台规格与政策容易变化。发行就绪检查必须查询当次官方来源并记录链接和日期；无法核验时保持待确认。第三方词库只能发现线索，不能代替官方规则与人工语境判断。权利、隐私和敏感风险缺证据时不得判通过。

公开发布还必须明确“保留首映或投稿资格：需要 / 不需要”。未确认不能通过；需要时由 A 调用 `$manage-film-competition-submissions` 核实本届规则与公开条件，避免不可逆地损失投稿资格。

### 发布授权门

v0.75 首版只输出 `manual-copy`，不控制浏览器、不登录账号、不上传、不定时、不公开、不修改或下架内容。

```text
包装决定采用 ≠ 封面完成
封面完成 ≠ 最终发布包采用
最终发布包采用 ≠ 精确版本检查通过
检查通过 ≠ 上传授权
上传或草稿 ≠ 公开发布
没有真实回执 ≠ 已发布
```

## 9. 结果复盘

只有真实 PUB 回执和平台数据存在时复盘。若实际发布字段与最终发布包不同，以回执中的实际版本为分析对象并保留差异。每条结论分四层：

1. 数据事实。
2. 有样本边界的反馈。
3. 一个主要解释与至少一个替代解释。
4. 下一次只调整的一组变量。

没有真实数据只记录“等待观察”。单条作品不能确立或推翻长期账号方向，不把平台波动自动归因于作品质量。

## 10. 里程碑

| 里程碑 | 最小证据 |
| --- | --- |
| 后期成片完成 | 采用 CUT、真实路径和 D 成片质检 |
| 发行已就绪 | 采用 PUB、真实最终封面、唯一最终发布包及其输入哈希、明确首映/投稿决定和绑定精确版本的独立检查通过 |
| 公开发布已登记 | 真实平台、账号、实际发布字段、链接或明确回执、发布时间及与计划差异 |
| 单片发行复盘完成 | 真实数据窗口、事实、样本限制、主要与替代假设、下一次单一调整 |

发布是用户可选择的外部动作。未发布或尚未到观察窗口不等于制作失败，只保持相应里程碑待定。

## 11. 返修路由

| 证据指向 | 返回 |
| --- | --- |
| 故事、人物、主题、情绪或可见行动 | B |
| 资产、表演、镜头、提示词、生成一致性 | C |
| 素材组合、节奏、声音、字幕、调色或成片技术 | D |
| 标题、正文、发行封面、平台字段或包装反馈 | E |
| 权利风险、无法判断、跨岗位或里程碑 | A |

E 只能提出上游返修建议并交回 A，不能直接修改 B/C/D。单条数据不触发全流程重做。

## 12. 写回与交接

B/C/D/E 在任务完成、暂停、切换岗位或结束本轮时按本岗位契约更新最近交接：

```text
本次完成：
已经写入：
仍然待定：
发现的问题：
建议下一步：
需要 A 判断：
```

A 验收真实证据后更新自己的当前任务和里程碑。岗位不直接修改 A。

## 13. 流程改进与旧项目兼容

A/B/C/D/E 在真实任务中观察到重复返工、遗漏、交接失败、职责冲突、重复手工、工具失败、证据缺口或契约不清时，调用 `$improve-ai-film-workflow` 登记 WFI。普通创作修改不记录，日志不自动改总工作流。

机器安装 v0.75 不代表当前项目已迁移：

- v0.75 且真实存在 E：允许 D → A → E。
- v0.7 或更早且无 E：继续按原项目契约运行，不补建 E。
- 共用 Skill 必须从当前项目入口和文件结构判断，不能只看机器配置版本。
- 迁移旧项目需要单独明确授权。

比赛投稿管理仍是五岗位之外的根级能力，不新增第六聊天框。项目有 E 时可读取真实公开链接与发行状态；旧项目无 E 时保持兼容。

## 14. 工具中立

核心文件只保存平台无关的事实、稳定 ID、约束、输入输出和证据。具体生成、剪辑、封面或发布工具通过可替换适配器执行。首版默认 `manual-copy`：

```text
AI 输出可复制任务包
→ 用户在外部工具执行
→ 用户带回文件、链接、回执或数据
→ 所属岗位核验并登记
```

没有适配器时不猜参数、不虚构执行。
