# 小陌AI影视工作流总框架 v0.6

状态：活动版本。已完成隔离评测并获得用户明确晋升确认，是新项目默认版。

## 1. 目标

v0.6 保留 A/B/C/D 四岗位和滚动制作，把 v0.5 的协作外壳补成可从点子运行到成片、发布与复盘的生产闭环：

```text
点子 -> 剧本 -> 资产 -> 色卡 -> 表演 -> 镜头 -> 提示词
-> 生成与结果诊断 -> 剪辑成片 -> 发布 -> 数据与流程复盘
```

项目文件保存长期事实，聊天和工具只是可替换的执行岗位。一个岗位可以调用多个单职责 Skill，但不能改变文件归属。

## 2. 新项目启动

创建新项目时使用 `$start-ai-film-project`。它负责版本化目录、模板复制、完整性校验、项目身份和四岗位原始提示词，并交付一段可复制的单提示词启动包；不参与创作，也不是第五岗位。

文件夹建立后，在 Codex 中选择该文件夹创建项目，并把单提示词启动包作为第一个任务的第一条消息。当前任务成为 A，再创建 B/C/D 三个独立本地任务；项目内 `开始这里.md` 仍是唯一日常入口，后续按 A 的单一当前任务进入 B/C/D。

## 3. 四岗位与写入权

| 岗位 | 负责 | 独占写入 |
| --- | --- | --- |
| A_总控流程 | 当前状态、单一任务、完成标准、岗位切换、里程碑 | `A_总控.md` |
| B_故事剧本 | 点子、故事骨架、人物、主题、剧本、制作启动判断 | `B_故事剧本.md` |
| C_视觉生成 | 资产设计、色卡、表演、镜头、提示词、生成、结果诊断、生成素材 | `C_视觉生成.md`、`资产设计/`、`色卡/`、`表演设计/`、`镜头规划/`、`提示词卡/`、`生成记录/`、C 资产 |
| D_后期发行复盘 | 剪辑、声音、字幕、调色、成片质检、发布包、数据与流程复盘 | `D_后期发行复盘.md`、`后期方案/`、`发布包/`、D 资产 |

其他岗位可以读取 A 指定的关联内容，但不能代写。C 的生成视频保存到 `assets/视频/生成素材/`；D 的粗剪和成片保存到 `assets/视频/剪辑成片/`，双方不得覆盖对方文件。

## 4. 统一执行契约

每个项目模式 Skill 必须明确：

```text
读取范围
写入范围
确认门
负责的 ID
停止条件
交接目标
```

执行时遵守：

1. 读取 `开始这里.md`、A、本岗位主文件和 A 指定的最小关联材料。
2. 记录准备写入文件的初始 SHA-256；写入前再次核对。文件已被其他聊天修改时停止，不覆盖并发进展。
3. 草案阶段零写入，不写任何项目文件。
4. 用户明确采用后，才创建或更新采用产物。
5. 用户暂停、切换岗位或结束本轮但没有采用时，只写本岗位主文件中的待定摘要和最近交接，不创建采用产物。
6. 媒体生成、媒体文件改写、上传、发布等外部或有副作用动作必须获得明确执行授权。准备方案不等于执行授权。
7. 工具不可用、输入缺失或执行失败时返回真实状态和人工交接，不声称完成。

“采用”“按这版写入”“就这样”属于采用确认；“先看看”“可能”“不一定”不属于确认。“请生成”“请剪出文件”“请上传发布”才属于对应外部动作授权。

## 5. 状态、分析标签与版本

项目持久状态只使用：

```text
待定
采用
停用
```

“候选、开放问题、用户确认、AI 推断、已拒绝”等是对话和分析标签，不是第四套持久状态。写回时映射为：

- 已明确接受的内容 -> `采用`
- 尚在比较、存在开放问题或只是 AI 推断 -> `待定`
- 用户明确拒绝或被采用替代方案取代 -> `停用`，并保留简短原因

稳定 ID 与版本分开。同一对象功能不变时保留 ID 并递增 `v01`、`v02`；功能根本改变时停用旧 ID、分配新 ID。停用编号不回收。

对象的**当前状态**以所属岗位主文件中的索引为权威；详细版本文件保留该版本建立时的历史证据，不因后续替代而静默改写。新版本采用时，主索引和新版本记录必须同时写清旧版本停用、新版本采用、稳定 ID 是否沿用；查询当前可用版本时不得只读取旧版本文件头。

## 6. ID 所有权

| ID | 对象 | 唯一分配岗位或 Skill |
| --- | --- | --- |
| `Sxx` | 可进入制作的剧本段落 | B_故事剧本 |
| `Axx` | 角色、场景、道具等视觉资产 | `$design-ai-film-assets`，C 岗位 |
| `Vxx` | 从采用镜头计划贯穿生成与剪辑的稳定镜头 | `$plan-ai-shots-and-previs`，C 岗位 |
| `CUTxx` | 首个可比较粗剪或成片 | `$edit-and-finish-ai-film`，D 岗位 |
| `PUBxx` | 采用的发布版本 | `$package-video-release`，D 岗位 |

A 只记录和路由这些 ID，不代替所属岗位创建。普通失败、无价值微调和临时脑洞不分配 ID。

## 7. 滚动生产路线

```text
A 使用 $orchestrate-ai-film-project 安排一个任务
-> B 使用 $shape-story-skeleton / $develop-screenplay-from-idea
-> B 采用可制作段落并分配 S
-> A 转交 C
-> C 使用 $design-ai-film-assets 建立 A 资产规格
-> 使用 $cinematic-palette-architect 为采用 A 建立基础资产色卡
-> 复杂角色段落先用 $direct-ai-character-performance 定场景表演主线
-> 使用 $plan-ai-shots-and-previs 建立 V 镜头
-> 再用表演 Skill 按 V 落位
-> 镜头色彩、光线或最终 Look 需要单独控制时，使用 $cinematic-palette-architect 为采用 V 建立最终镜头色卡
-> 使用 $prompt-generator 建立提示词卡
-> 使用 $produce-and-review-ai-media 生成或接收结果、诊断并登记
-> A 转交 D
-> D 使用 $edit-and-finish-ai-film 建立 CUT
-> 使用 $package-video-release 建立 PUB
-> 使用 $review-ai-film-results 完成数据与流程复盘
-> A 关闭里程碑或安排下一轮
```

制作启动不要求全剧本彻底锁定，但必须满足：当前批次内容清楚；待定项不会让本批资产整体作废；用户接受边制作边调整。

## 8. 工具中立与适配器

核心 Skill 只保存模型无关的创作事实、稳定 ID、约束、输入输出和证据。具体生成模型、网页工具、剪辑软件或发布平台通过按需 reference 适配。

v0.6 默认使用 `manual-copy`：

```text
AI 输出可复制任务包
-> 用户在外部工具执行
-> 用户把结果文件、链接或数据带回
-> 所属岗位检查并登记
```

适配器只能翻译字段、能力、参数和人工步骤，不能改写采用的剧本、表演、镜头或资产事实。没有适配器时保持通用表达，不猜测平台参数。

## 9. 结果证据

重要资产、色卡、生成结果、CUT 和 PUB 至少记录：

```text
稳定 ID 与版本
状态
文件或链接
来源工具或 manual-copy
关联剧本、资产、镜头、提示词卡或上游版本
实际观察
问题归因
下一步
```

本地文件存在时记录相对路径；需要防止误覆盖或证明版本时记录 SHA-256。不要把不存在的媒体、未执行的剪辑或未完成的发布写成事实。

## 10. 返修路由

| 证据指向 | 返回 |
| --- | --- |
| 故事、人物、主题、情绪或可见行动不足 | B |
| 角色/场景/道具规格或跨镜一致性 | C 资产设计 |
| 角色目标、潜台词、动作因果或逐镜表演 | C 表演 |
| 机位、覆盖、连续性、首尾状态或镜头功能 | C 镜头 |
| 模型表达、提示词结构或适配器参数 | C 提示词 |
| 生成工具能力限制或单次生成技术失败 | C 生成记录 |
| 素材组合、节奏、声音、字幕、调色或成片标准 | D 后期 |
| 标题、封面、平台规格、发布或数据复盘 | D 发布/复盘 |
| 无法判断、跨岗位或影响当前里程碑 | A |

一次生成失败不能直接触发全故事重写。只有具体证据指向上游事实时才返回对应岗位。

## 11. 写回与交接

B/C/D 在任务完成、暂停、切换岗位或结束本轮时更新本岗位“最近交接”：

```text
本次完成：
已经写入：
仍然待定：
发现的问题：
建议下一步：
需要 A 判断：
```

A 读取最近交接后更新自己的当前任务和里程碑。B/C/D 不直接修改 A。

## 12. 上下文重开

聊天跑偏、上下文过长、开始反复，或聊天记忆与项目文件冲突时，新开同岗位聊天。新聊天只读取入口、A、本岗位主文件和 A 指定的关联材料，不迁移旧聊天全文。

```text

```

`manage-film-competition-submissions` 是工作流根级的独立投稿管理 Skill，不属于 A/B/C/D 四岗位，不新增第五岗位或项目聊天框；默认只读，采用后只维护工作流根的集中式 `投稿管理/`，不得把比赛数据写入项目主文件。

所有 Skill 均不得改变四岗位分工，不得代写其他岗位主文件。飞书和其他在线文档只作复制与展示，本地 Markdown 是项目事实源。
