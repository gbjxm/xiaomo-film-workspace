# 小陌AI影视工作流总框架 v0.5

状态：当前新项目使用版。

## 1. 核心修正

v0.5 不增加创作阶段，只解决四个聊天框之间的协作问题：

```text
谁负责
当前只做什么
确认后写到哪里
什么时候切换或重开聊天
```

项目文件保存长期事实，聊天框只是可以随时重开的工作岗位。

### 新项目启动前置工具

创建全新项目时，先运行工作流根目录的 `安装工作流.ps1`，再使用 `$start-ai-film-project`；日常只提供一个基础项目名。它会从当前 v0.5 权威模板创建不覆盖历史项目的 `<项目名>_vN` 文件夹，校验模板复制结果，写入便携的项目身份与根目录说明，打开项目文件夹，并交付 A/B/C/D 四段启动词。

`$start-ai-film-project` 位于四岗位之前，只负责项目初始化，不是第五岗位，也不参与具体创作。项目建立后，`开始这里.md` 仍是唯一日常入口；先启动 A，再按 A 的当前任务进入 B/C/D。

## 2. 四个岗位

| 聊天框 | 负责 | 独占写入 |
| --- | --- | --- |
| A_总控流程 | 当前状态、单一任务、岗位切换、里程碑 | `A_总控.md` |
| B_故事剧本 | 点子、故事、人物、主题、剧本、制作启动判断 | `B_故事剧本.md` |
| C_视觉生成 | 视觉、角色表演与动作设计、镜头规划与预演、资产、提示词、生图、生视频、生成问题 | `C_视觉生成.md`、`表演设计/`、`镜头规划/`、`提示词卡/`、生成素材 |
| D_后期发行复盘 | 粗剪、后期、声音、发行、三类复盘 | `D_后期发行复盘.md`、剪辑成片与后期资产 |

一个主文件只有一个负责岗位。其他岗位可以读取，但不能代写。

C 的生成视频保存到 `assets/视频/生成素材/`，D 的粗剪和成片保存到 `assets/视频/剪辑成片/`，双方不覆盖对方文件。

## 3. 日常协议

全系统只保留六条日常规则：

1. 项目文件是长期记忆，聊天记录不是。
2. 一个聊天框只维护自己的主文件。
3. A 每次只安排一个当前任务，并定义本次完成标准。
4. B/C/D 平时自然对话，不使用固定汇报格式。
5. 用户明确确认、暂停、切换岗位或结束本轮时，当前聊天框自动写回。
6. 切换岗位、完成里程碑、出现跨领域问题或明显跑偏时回 A；普通连续创作不回 A。

明确确认包括“就这样”“采用这个”“按这个做”等表达。“可能”“先看看”“不一定”不算确认。

## 4. 滚动制作

```text
B 发展故事和剧本
→ 第一批制作内容达到最低可用线
→ A 转交 C；复杂角色段落先定场景表演主线，再规划镜头并逐镜落位
→ C 制作视觉资产、提示词和生成素材
↔ C 的创作问题经 A 返回 B
→ D 边接收素材边粗剪
↔ D 的素材问题经 A 返回 C
→ 后期、发行与复盘
```

制作启动不要求剧本彻底锁定，也不要求固定数量的场景。满足以下条件即可：

- 第一批准备制作的内容已经清楚。
- 当前待定项不会让这批资产整体作废。
- 用户接受边制作边调整。

## 5. 写回与交接

B/C/D 只有在任务完成、暂停或切换岗位时，才整理交接回执：

```text
本次完成：
已经写入：
仍然待定：
发现的问题：
建议下一步：
需要 A 判断：
```

回执写入本岗位主文件。A 读取回执后更新 `A_总控.md`，B/C/D 不直接修改总控文件。

## 6. 最小状态与编号

内容状态只使用：

```text
待定
采用
停用
```

“采用”内容只有在用户确认替代方案后才覆盖。

编号由 AI 在对象进入制作、成为采用版本或具有重要复盘价值时自动分配：

```text
S01    剧本段落
A01    角色、场景或道具资产
V01    从确认的计划镜头开始贯穿生成与剪辑的稳定镜头
CUT01  粗剪或成片
PUB01  发布版本
```

稳定 ID 与版本分开，例如 `A01` 的当前版本可以是 `v02`。`V01` 不是某个生成文件；同一镜头功能不变时保留 ID 并递增版本，功能根本改变时停用旧 ID、分配新 ID，编号不回收。普通失败、无价值微调和临时脑洞不编号、不长期记录。

## 7. 返修路由

```text
故事、人物、情绪问题 → B
资产、提示词、生成问题 → C
剪辑、声音、发行问题 → D
无法判断 → A
```

一次生成失败不能直接触发全故事重写。C 判断素材的视觉和技术可用性，D 判断素材在叙事节奏和剪辑组合中的可用性。

## 8. 上下文重开

聊天框明显跑偏、上下文过长或文件事实与聊天记忆冲突时，直接新开同岗位聊天框。

新聊天只读取：

```text
开始这里.md
A_总控.md
本岗位主文件
A 指定的关联段落、表演方案、镜头方案、提示词卡或资产
```

旧聊天不需要迁移；已写入文件的内容才算可以继续复用的项目事实。

## 9. Skill 与工具边界

- `$start-ai-film-project` 仅用于全新项目建立前的版本化目录、模板初始化、验证、打开目录和四岗位启动词交付；它不是第五岗位，项目建立后退出日常流程。
- 现有 Skill 可以在所属岗位内部按需调用。
- C 遇到对白、关系变化、关键反应或动作戏时，先调用 `$direct-ai-character-performance` 建立场景表演主线；空镜、普通插入和简单机械动作可以跳过。
- 场景表演主线采用后，镜头 Skill 读取它并保持人物目标、关系变化、表演节拍、动作因果和首尾状态；镜头方案采用后，再调用表演 Skill 沿用既有 V 编号完成逐镜落位。
- C 遇到镜头规划、分镜、镜头覆盖、AI 视频拆镜、静态预演或动态预演时，调用 `$plan-ai-shots-and-previs`。
- `$plan-ai-shots-and-previs` 先确认段落任务、视点、调度、空间与轴线基准、视觉推进和覆盖策略，并在生成前检查连续性与镜头组，再分配稳定 V 编号并展开逐镜方案；确认后的方案写入 `镜头规划/Sxx_镜头方案.md`，同步 C 的镜头规划与视频片段索引，但实际剪辑仍由 D 负责。
- 表演决定角色做什么、为什么做和怎样反应；镜头规划决定摄影机怎样看、怎样拆和怎样衔接；`$prompt-generator` 负责把镜头方案与结构化表演块转成模型表达；D 负责真实声音、剪辑和成片判断。
- `$direct-ai-character-performance` 不改剧本或镜头，不输出最终提示词，不生成或诊断媒体，也不执行真人危险动作；`$plan-ai-shots-and-previs` 不重写故事、不重新解释已采用表演、不输出最终提示词、不生成媒体、不诊断结果，也不执行实际剪辑。
- 生成前的表演、调度、连续性和镜头组检查属于 C；实际组合、节奏、声音和成片判断仍由 D 负责。
- Skill 不改变四岗位分工，也不能写入其他岗位的主文件。
- 本框架不训练 Skill，不进入具体项目创作。
- 飞书只作复制和展示，本地 Markdown 是主事实源。
