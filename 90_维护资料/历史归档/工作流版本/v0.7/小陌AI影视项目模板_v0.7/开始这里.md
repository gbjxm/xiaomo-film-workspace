# 开始这里

> 本项目使用“小陌 AI 影视工作流 v0.7”。新建项目由 `$start-ai-film-project` 从权威模板创建。
> 本文件是日常入口；项目根目录以本文件所在目录为准，不依赖旧聊天或旧电脑路径。

## 日常路线

```text
A 分配一个任务
→ B/C/D 完成该任务
→ 明确确认后写回
→ 更新最近交接
→ 返回 A 分配下一任务
```

同一 A 当前任务内的追问、局部返修和同岗位续办不必返回 A；只有任务完成、跨岗位、影响里程碑或出现阻塞时才回 A。

完整生产链为：

```text
点子 → 剧本 → 资产 → 色卡 → 表演 → 镜头 → 提示词 → 生成反馈
→ 后期剪辑 → CUT 成片与质检
```

## 必须遵守的契约

1. 项目文件是长期事实源，聊天记录不是。首次进入任务只读取本文件的共享契约与本岗位启动词，跳过其他岗位启动词；同一任务内未变化的已读内容直接复用。
2. A 每次只分配一个任务；B/C/D 只执行 A 当前分配给本岗位的任务。
3. 每个岗位只写自己的主文件和专属目录，其他文件只能读取。
4. 草案阶段零写入。只有“明确采用”才写成采用；暂停、切换岗位或结束本轮只能写“待定摘要＋最近交接”。
5. 项目持久状态只使用 `待定`、`采用`、`停用`。“候选”“开放问题”“用户确认”“AI 推断”只可作为对话标签。
6. 草案、咨询、诊断和只读检查不计算 SHA-256。明确采用并即将写入时，先重读目标并记录 SHA-256，紧邻写入前再次核对；值变化时停止，不覆盖。
7. 生成媒体和执行剪辑需要各自单独的明确执行授权。授权采用方案不等于授权执行外部动作。发布与发布后复盘当前冻结，不进入本项目活动路由。
8. A/B/C/D 若观察到重复返工、遗漏、交接失败、职责冲突、重复手工步骤、工具失败、证据缺口或契约不清，使用 `$improve-ai-film-workflow` 静默写入 `流程改进日志/`。普通创作修改不记录；日志由该 Skill 独占写入，不改变岗位原有文件边界，也不自动修改总工作流。阻塞、覆盖、数据丢失、权限和安全风险仍须立即报告。
9. 没有可用工具时交付 `manual-copy` 人工执行包，不声称已生成或已剪辑。

“采用这个”“按这个定稿”可视为采用确认；“先看看”“大概这样”“以后再说”仍是待定。遇到含糊表达只问一个最关键的问题。

## 文件归属

| 岗位 | 独占写入 |
| --- | --- |
| A_总控流程 | `A_总控.md` |
| B_故事剧本 | `B_故事剧本.md` |
| C_视觉生成 | `C_视觉生成.md`、`资产设计/`、`色卡/`、`表演设计/`、`镜头规划/`、`提示词卡/`、`生成记录/`、生成素材 |
| D_后期剪辑 | `D_后期剪辑.md`、`后期方案/`、剪辑成片、声音、字幕、调色与母版资产 |

## 问题路由

```text
故事、人物、情绪问题 → B
资产、表演、镜头、提示词、模型限制或生成问题 → C
剪辑、声音、字幕、调色、视效修整、成片与母版问题 → D
标题、封面、平台发布或发布后数据复盘 → 当前冻结，返回 A 保持待定
无法判断、跨岗位冲突或里程碑关闭 → A
```

一次生成失败不能直接触发全故事重写。先由 `$produce-and-review-ai-media` 分类，再只返修最小责任层。

每个任务必须写清：执行岗位、输入、明确不做、完成标准、写回位置。不要代替 B/C/D 制作内容。
