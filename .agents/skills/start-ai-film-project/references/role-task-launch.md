# V1 岗位任务初始化

用于用户明确要求在已存在 V1 项目中“启动六岗位、建齐岗位、补齐岗位任务”，或执行脚本返回的六岗位启动包。仅想获得启动词时只交付，不执行创建；明确要求初始化则直接推进，不重复询问是否创建。

## 入口与读取

调用 `scripts/get_role_launch.ps1 -ProjectRoot <项目绝对路径>`。它只读取项目入口、能力与路径信息，返回一个完整 `launchPrompt`、五段 `standbyPrompts` 和六个 `roleTitles`，不创建目录、修改文件或创建 Codex 任务。不运行 `start_project.ps1`，避免给已有项目另建版本。`ReadRoot` 仅供新项目创建器内部校验临时副本，不是用户入口参数。

调用结果成功只证明启动包生成；不能报告任务已创建。向用户交付时原样展示 `launchPrompt` 一个代码块，不改写成“统一任务承担六岗位”，不拆成六次复制。新建 V1 项目也通过同一函数生成启动包，旧 v0.9/v0.8 分支保持各自行为。

实际执行先检查当前工具目录中的 Codex 原生项目、任务查询、改名、创建能力；工具名可能有命名空间，以真实 schema 为准，不凭名称伪造参数。工具不可用时保留状态，报告缺失能力，原样交付五段待命消息供手动创建；不能代用子代理、独立 CLI 会话、直接写入数据库或修改应用开关。任务工具恢复属于 Codex 环境排查，不由修改工作室能力或文本运行时实现。

### 路径与复制文本

Windows 绝对路径先统一分隔符、大小写、尾部分隔符和 `\\?\` 长路径前缀后比较；UNC 保留服务器与共享名，不用文本前缀匹配代替相等。不得猜相近项目或按最新日期选目录。

若收到的路径含 `\_`，先检查原路径是否存在。只有原路径不存在、去掉紧邻下划线的 Markdown 转义后唯一等于真实当前 cwd，且当前目录的九个入口均存在时，才判为传递转义；简要告知后以真实 cwd 调用 `get_role_launch.ps1`，重新生成并校验完整启动包。用重新生成的路径、文件名、工具名及待命消息继续，不直接对整段消息执行全局替换。原路径存在、结果仍不同或有歧义时停止。辅助脚本不会替用户选择项目。

交付完整启动词保持一个原样代码块，不给 `_` 或 `<` 添加转义。若项目已有保存的启动信息，可让目标任务直接读取该文件；有旧启动包时仍以当前正式 helper 重新生成的结果为准，不要求用户再次复制长文。

### 最近任务列表不完整时的只读补查

`list_threads` 的 `limit` 是全局近期数量，满额 50 条不代表目标项目有 50 个任务，也不提供“目标项目为空”的证明。优先使用原生工具实际支持的定向查询；当前 schema 没有项目筛选或翻页时，不编造参数、不反复扩大 limit。

已由原生项目工具核实唯一 **本机 local 项目** 的 projectId 与 cwd 后，调用本 Skill 的辅助脚本：

```powershell
python -X utf8 "<本 Skill 目录>/scripts/query_local_role_tasks.py" --project-id "<真实 projectId>" --project-root "<已核验绝对路径>" --current-thread-id "<当前真实 threadId>"
```

脚本从本机 `CODEX_HOME` 定位状态；仅环境变量缺失时传明确的 `--codex-home`，不搜索其他用户目录。它用 SQLite `mode=ro`、`query_only` 读取任务 ID、标题、cwd、归档状态和项目 ID，并与应用 `thread-project-assignments`、目标项目侧栏 ID 交叉核对。数据库 `project_id` 为空时不能直接判为不属于项目。不同项目同名任务不计入；同目录但归属未知或冲突的活动任务必须报告，不静默忽略。当前 A 仅保留当前 threadId 与精确 cwd 的既有例外。

只在 `success=true` 且 `complete=true` 时用 `activeThreads` 继续同岗去重；`archivedThreads` 是历史，不唤醒或删除。完整枚举不代替角色判断：第二个 A、同岗重复或不明标题仍先澄清。脚本不读取对话正文、令牌或模型配置，不更改索引、项目归属、客户端设置或任务；任务的创建、改名和待命核验仍走原生工具。它仅为当前本机存储结构的兼容补查，不能证明其他设备或远程项目的完整性。

本机状态缺失、结构不支持、目标候选超过 50 个、归属冲突或读取期间相关元数据变化时返回不完整及具体原因。先按真实原生能力补查；仍不能唯一确认才停止，不能据此判缺失或重试创建。不要在每个项目临时拼一段新的数据库脚本。

## 创建与复用

按 `launchPrompt` 的项目归属、cwd 和重复任务条件执行；只能在用户指定的同一已注册本地项目创建可见任务。当前任务为 A，B/C1/C2/D/E 有唯一同岗任务则复用，缺失才创建；查询不完整时先定向补查，不能把未看见当作不存在。不同标题但可能属于同一岗位时先确认身份，不能按标题机械重复创建。已有任务只登记复用，不自动发消息、领取工作集或改变内容。

新任务的初始消息逐字使用对应 `standbyPrompts`，不附整个旧聊天、工作稿或其他岗位资料。创建为异步动作时，只用紧凑状态核对新任务的待命回复；`title/projectId/cwd` 与真实创建回执一致才报告已创建，收到待命回复才报告已待命。结果不明或失败时停止，不删除、不自动重试；再次执行仍先查询，不能重复创建。

每次创建前刷新目标项目元数据；已存在的岗位跳过。保存本次真实创建回执中的任务 ID。新任务未立即出现在最近列表时，用同一只读补查核对项目归属，并以该 ID 的 `read_thread` / `wait_threads` 核对 cwd、标题和待命回复；暂不可读就标“已创建、待命未核实”，不能再次创建。再次初始化也先查真实任务，无需另建一份项目岗位台账。

初始化只建立岗位入口，不启动剧本阶段，不写专业文件，不创建或激活工作集，不执行生成、剪辑、导出或发布。当前 A 完成后等待用户具体请求；专业后续工作遵循项目现有 V1 契约与已确认设定。空的待命任务不使用 PrepareHandoff；真正接替同一已有工作集时才按共同契约交接，不恢复旧单岗续接或 A 派岗门禁。

## 验收范围

脚本回归验证覆盖新建和已有项目的启动包一致、V1 六岗位及五段独立短消息、两种工作资料布局、错误入口拒绝、零项目写入、旧版输出兼容。自动建岗还须真实工具调用及侧栏任务回读；用模拟工具或字符串检查只能证明对应层级，不能代替真实创建验收。

只读补查另用隔离任务索引验证：全局近期任务超过 50、数据库项目 ID 为空但应用归属有效、Windows 长路径、同目录归属冲突、重复/归档岗位、目标枚举超限、未知结构、当前 A 例外以及零写入。只读查询返回六岗位不等于本轮又执行了一次创建。
