# 来源与定位规范

## 三级身份

- `work_id`：一部独立著作的稳定身份。
- `edition_id`：特定语言、译本、出版版本或数字化版本。
- `file_id`：一个具体文件的稳定身份；内容由 SHA-256 锁定。

同一文件只能属于一个 `edition_id`，一个 `edition_id`只能属于一个 `work_id`。不同格式或译本可以共享 `work_id`，但不得共享 `file_id`。

## 文件角色

- `canonical`：当前首选结构化提取源。
- `locator`：用于页码、版面或视觉核对。
- `crosscheck`：用于翻译差异和疑难段落互校。
- `alternate`：同一著作的另一数字化版本。
- `fallback`：主格式失败时使用。
- `archive`：原始压缩包，只登记和校验哈希。

角色不表示内容更权威。作者、译者、出版社和版本差异必须在逐书来源地图目标中继续核对。

## PDF定位

PDF定位必须至少包含：

```json
{
  "type": "pdf_page",
  "pdf_page": 42,
  "print_page": null,
  "text_hash": "sha256:..."
}
```

- `pdf_page` 从 1 开始，永远表示 PDF 文件页序。
- `print_page` 只有在版面上清楚可见并核对后才填写，可为罗马数字或数字字符串。
- 不得通过固定偏移批量猜测印刷页码。
- 文本层和OCR文本都保存短哈希，用于发现内容变化。

## EPUB定位

EPUB定位必须至少包含：

```json
{
  "type": "epub_anchor",
  "chapter_href": "Text/chapter03.xhtml",
  "heading": "章节标题",
  "paragraph_index": 17,
  "text_hash": "sha256:..."
}
```

- `chapter_href` 必须存在于该 EPUB 的 spine 或 manifest。
- `paragraph_index` 从 1 开始，只在当前章节文件内部计数。
- `heading` 是阅读提示，不是唯一主键。
- 不生成虚构页码。

## 证据状态

- `text_layer`：来自可直接读取的PDF或EPUB正文。
- `ocr_verified`：OCR结果已经人工对照版面。
- `ocr_unverified`：OCR结果尚未核对，只能进入草稿或待核区。
- `user_note`：用户笔记。
- `external`：原书以外资料。

最终知识卡至少需要一条 `text_layer` 或 `ocr_verified` 的书籍证据。

## 文件变化

每次运行来源校验时重新计算 SHA-256。哈希不一致时：

1. 不覆盖旧登记；
2. 在失效报告中列出 `file_id`；
3. 将该文件关联的提取结果、定位和知识卡视为需要重验；
4. 完成新版本登记后再更新。
