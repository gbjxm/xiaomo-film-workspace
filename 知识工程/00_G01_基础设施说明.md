# G01｜原书接收与知识卡基础设施

## 当前边界

- 本目录保存来源登记、格式提取、知识卡主数据、核验记录和确定性脚本。
- 原书只保留在 `D:\book`，不得移动、改名或写入。
- 工作流根目录下的 `skills/develop-screenplay-from-idea` 只在后续目标接收验收后的精炼知识。
- G01 不提炼任何正式书籍知识，不修改现有 Skill，不建立跨书理论结论。

## 五套理论与九部著作

| 系统 | 著作 |
|---|---|
| STC | 《救猫咪1》《救猫咪2》《救猫咪3》 |
| EGR | 《编剧的艺术／戏剧写作的艺术》 |
| TRU | 《故事写作大师班》 |
| FLD | 《电影剧本写作基础》 |
| MCK | 《故事》《对白》《人物》 |

McKee《故事》的简体 EPUB、简体 PDF、简体 TXT、MOBI、压缩包和繁体《故事的解剖》属于同一 `work_id`。繁体《故事的解剖》只承担翻译互校，不重复生成知识卡。Truby《故事写作大师班》的英文原名为 *The Anatomy of Story*，与 McKee《故事》不是同一著作。

## 数据层

1. `配置/source-plan.json`：人工确认的系统、著作、版本和文件角色。
2. `来源/source-registry.json`：脚本生成的文件哈希、格式状态和定位能力。
3. `提取/`：PDF、EPUB或OCR的可复核中间结果。
4. `章节地图/`：后续逐书建立的完整覆盖地图；G01只提供模式。
5. `知识卡/`：后续逐书建立的可执行知识；G01只保存模拟测试。
6. `核验/`：来源、OCR、知识卡和失效检查报告。
7. `脚本/`：只完成确定性读取、登记、定位和校验，不负责解释书中理论。

## 运行顺序

```text
source-plan.json
→ inventory_sources.py
→ source-registry.json
→ validate_registry.py
→ PDF/EPUB提取或OCR
→ 章节地图
→ 知识卡
→ validate_card.py
→ audit_staleness.py
→ 后续Skill集成
```

在 PowerShell 中先进入本 `知识工程` 目录，再使用相对路径运行脚本，例如：

```powershell
.\.venv-ocr\Scripts\python.exe .\脚本\run_tests.py
```

`配置/source-plan.json` 中的 `source_root` 是本机外部原书位置。换电脑后需要单独准备原书并按实际位置更新该配置；核验目录中的历史绝对路径只代表当时证据，不是当前执行入口。

## 禁止事项

- 不用文件名相似度推断作者观点。
- 不把 PDF 页序写成印刷页码。
- 不给 EPUB 伪造页码。
- 不让 `[OCR，待核对]` 支撑已验收的作者主张。
- 不让用户笔记、外部补充或 AI 短片适配提高来源忠实度。
- G60 前不合并五套理论；跨书关系只能记录为 `link_only`。
